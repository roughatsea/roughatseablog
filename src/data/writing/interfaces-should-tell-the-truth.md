Small rule: make the thing say what it is doing.

If a control, layout, or motion obscures consequence, it is doing extra work for the reader.

Questions to write on the margin:

- Where does this lead?
- What does this control change?
- How will I explain this to myself later?

This is less design doctrine than a habit for clearer notes: label states, preserve hierarchy under strain, and use motion to point, not to distract.

A polished interface can still be dishonest.

It happens when a button looks harmless but triggers a destructive action, when a loading state appears frozen, when hierarchy is communicated only by color, or when animation hides where information moved.

Visual quality is not decoration applied after the product works. It is part of how the product explains itself.

## State should be visible

People should be able to answer a few questions without reverse-engineering the application:

- Where am I?
- What can I do here?
- What is happening now?
- What changed because of my action?
- Can I recover if this is wrong?

This is why mundane details matter: current navigation states, descriptive labels, disabled controls that explain why, meaningful progress feedback, and confirmation proportional to consequence.

## Hierarchy should survive bad conditions

A layout is not finished when it looks good on the designer's screen. It should remain understandable on a narrow viewport, at 200% zoom, with a long title, in bright sunlight, or when motion is disabled.

Semantic HTML, resilient spacing, fluid type, visible focus styles, and strong contrast are not separate accessibility decorations. They are how the hierarchy keeps telling the truth when conditions change.

## Motion should explain geography

Animation is useful when it answers “where did that come from?” or “what changed?” It becomes noise when it merely delays access to the next state.

A restrained transition can preserve context between pages. A reduced-motion preference should remove the transition without removing meaning. The interaction remains honest either way.

## Style follows intent

A distinctive site does not need a pile of effects. It needs a coherent point of view carried through typography, spacing, color, language, and behavior.

The result feels stylish because its decisions agree with one another—and trustworthy because those decisions help the interface describe what is actually happening.
