A note: when the purpose shifts, the tools should follow.

I once spent time keeping a complex site running because it was familiar. The lesson was not that the system failed—only that it no longer solved the question I cared about.

Consider this checklist when the architecture feels heavy:

- What problem did this layer originally solve?
- Does it still solve that problem clearly?
- Can the idea live in a smaller form (a file, a page, a short note)?

If the answer to the last question is yes, prefer simplicity. Keep the record of what you removed; the archive is the map to the route you took.
