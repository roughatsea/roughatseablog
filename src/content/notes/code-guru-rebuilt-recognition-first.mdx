# Code Guru Rebuilt

This field guide assumes that you can already program. Its purpose is to connect practical instincts—including ideas you may have discovered independently—to the vocabulary used in code reviews, design discussions, interviews, architecture work, and technical literature.

It contains all 205 concepts in the rebuilt handbook. The catalog is selective about *attention*, not about *coverage*: three reading tiers tell you what to learn first without deleting the useful long tail.

## How to use this guide

- Begin with **Core working vocabulary** for the fastest path into everyday professional conversations.
- Continue into **Broader professional vocabulary** when a project, role, or design discussion makes a concept relevant.
- Treat **Specialized / reference** entries as a long-tail lookup catalog. They are useful to recognize without being mandatory to memorize.
- Read the expanded examples first. They use named methods, explicit variables, and complete bodies so the responsibilities remain visible.
- Use **Modern shorthand** as a translation exercise. It shows how the same idea is compressed by lambdas, expression-bodied members, LINQ, or compact Python syntax.
- Finish with **Why these examples fit**. That walkthrough names the actual participants, identifies what varies or stays stable, and distinguishes neighboring terms.

The 205 code panels are collapsed by default so the catalog remains navigable. Open one when you want the C# and Python examples; within each language, the explicit version appears before any shorthand.

## The recognition-first reading pattern

1. **Name it.** Learn the accepted term and the problem it names.
2. **Recognize it.** Connect the term to a change pressure or programming move you may already know.
3. **Expand it.** Read conventional, explicit code before any compressed equivalent.
4. **Translate it.** Map lambdas and other shorthand back to the expanded version.
5. **Explain it.** Identify the exact roles, dependency direction, invariant, failure mode, or cost model.
6. **Bound it.** Learn the trade-off and the nearby concept that is easiest to confuse with it.

## Reading modern syntax without guessing

Compact syntax is easiest to learn by expanding it. Start with named behavior, then remove the names and type information one step at a time. The goal is fluency, not a rule that shorter code is better.

### C#: from named method to expression lambda

First, keep the behavior named and the parameter and return types visible:

```csharp
public static bool IsPriorityOrder(Order order)
{
    return order.Total >= 1000m;
}

Func<Order, bool> priorityRule = IsPriorityOrder;
```

`priorityRule` has the type `Func<Order, bool>`: it accepts an `Order` and returns a `bool`. Assigning `IsPriorityOrder` stores a reference to that named behavior.

Next, remove the method name while retaining the parameter type, braces, and explicit `return`:

```csharp
Func<Order, bool> priorityRule =
    (Order order) =>
    {
        return order.Total >= 1000m;
    };
```

Finally, the expression lambda lets C# infer the parameter type from `Func<Order, bool>`. Because the body is one expression, its value becomes the return value:

```csharp
Func<Order, bool> priorityRule =
    order => order.Total >= 1000m;
```

Mentally expand the arrow into the named method whenever the compact form feels ambiguous.

### Why context changes what a C# lambda means

```csharp
Func<Order, bool> inMemoryRule =
    order => order.Total >= 1000m;

Expression<Func<Order, bool>> queryRule =
    order => order.Total >= 1000m;
```

The first lambda becomes executable delegate code. The second becomes an expression-tree data structure that another component can inspect or translate, often into a database query. The characters after the equals sign look the same; the target type changes their meaning. Reading the type on the left—or the receiving parameter—is part of reading a lambda.

### Captured variables

```csharp
decimal threshold = 1000m;

Func<Order, bool> priorityRule =
    order => order.Total >= threshold;
```

`threshold` is not a parameter, so the lambda captures it from the surrounding scope. That state can outlive the current method and can change what later invocations observe. The catalog calls out capture whenever it affects ownership, lifetime, concurrency, or correctness.

### Python: named function before lambda

```python
def is_priority_order(order):
    return order.total >= 1000


priority_rule = is_priority_order
```

The shorthand is:

```python
priority_rule = lambda order: order.total >= 1000
```

A Python lambda creates a function object, just as `def` does, but its body is restricted to one expression. This guide uses a named function first and shows a lambda only when the anonymous form is realistic and still readable.

### Editorial and example policy

This guide does not reproduce Refactoring.Guru's diagrams or code samples. Each entry uses an expanded teaching example that keeps the participants and change pressure visible. A modern shorthand version follows only when it teaches a realistic translation rather than rewarding terseness for its own sake.

Walkthroughs refer to identifiers in the examples, explain why the structure earns the named term, and distinguish adjacent vocabulary where one fragment demonstrates several ideas. The reading tiers guide attention without removing the long tail of the catalog.
